# eo-01 — Monthly sensor quantification

**Round:** round-0001 (planned). **Host (proposed):** `codex`. **Role:** `agent_harness/roles/remote-sensing-quantification.md` (`standing`).

## Question
Compute true calendar-month S2 NDVI means for 2025/2026 (with median sensitivity), absolute and safely defined relative changes, SAR ancillary evidence and sensitivity with identical support.

## Inputs and authority
Inputs: frozen ROI/controls + AOI + monthly config + accepted dataset and QA reports. No interpreted national/official results.
Lab and Sentinel scientific/provenance policy has priority over this assignment. Data access is read-only outside new round output directories. No agent promotes knowledge or publishes a public release.

## Bounded step plan
1. Build 2025-06-01 to 2025-07-01 and 2026-06-01 to 2026-07-01 UTC Sentinel-2 L2A inventories. Check scene-specific acquisition times and calibration.
2. Calculate NDVI for each SCL-screened observation before taking the pixelwise arithmetic mean within each month; retain the pixelwise median as a robust sensitivity check. Preserve per-pixel observation counts and temporal support.
3. Enforce preregistered minimum N=3 clear observations per month (or mark unavailable); compare on common valid pixels only. Run N=2,3,5 sensitivity without backfilling missing.
4. Compute d_abs=NDVI26-NDVI25 and d_rel=d_abs/max(abs(NDVI25),eps). Report relative change only where NDVI25>=0.2, with eps=0.1; outside region mark undefined/unreliable. Store Δ and reference NDVI instead of percentage where unsuitable.
5. Check 10 vs 20m grid, reference/target registration, mask dilation, edge buffers 0/20/40/80m, crop/vary threshold, neighboring unchanged roads + forest controls. Do not assume a specific threshold is truth.
6. Separate road core vs road edges vs matched nonroad controls; add NDMI/NBR, Sentinel-1 VV/VH only as corroborative mechanisms with acquisition/orbit dates and caveats.
7. Try July and August matched month and multi-year (where available) as sensitivity, not as substituted June data.
8. Record raster output checksums, reproducible exact commands, hectare results under declared mask and reasons for missing data; generate offline maps per ROI.

## Output contract
Write `eo_measurements.csv, eo_claims.csv, map_manifest.json` into this round's artifacts directory or a new read-only-referenced run directory. For each claim include `claim_id`, `roi_id`, `period`, `status`, `evidence_ids`, `source_lineage`, `limitations`. Record tools, original observations, acquisition/registration dates, hashes, data/license terms and negative findings. An unavailable input produces a clearly marked blocker, not invented output.

## Acceptance / stop rules
PASS if monthly composites exist, pixel counts/coverage and common support checks pass, and no roads are labeled forest loss without approved forest mask. BLOCK if data sparse, dates unverified, calibration/reg uncertain.

## Review
Step plan and outputs require human approval at the declared graph gates. `actual_executions` is empty until a host actually performs the task. No unreviewed source is ground truth.
